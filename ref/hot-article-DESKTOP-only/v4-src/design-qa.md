## 复核中修复的问题

1. 带间距参数的标题曾落入 `pack` 默认居中，已统一左对齐。
2. 隐藏页签中的 Canvas 嵌入控件可能仍映射，覆盖当前稿件；圆角卡在 Map/Unmap 时显式同步嵌入窗口状态。
3. 动态候选标题和目录变量曾隐式绑定全局默认 Tk 解释器。在宿主/测试存在其他 Tk 根窗口时，可能出现标题选择不保存或目录空白；变量现显式绑定当前工作区。
4. 重新设定与分析完成后的滚动目标改为对应结果区域；重新选择立意仍保留写作风格，选择后返回第四步。

### test_article_workspace 偶发 TclError 排查

现象：单独循环运行 `tests/test_article_workspace.py`，约每 5–6 次有 1–2 项在 `MainWindow()`（`tk.Tk()` 引导）时失败，报 `couldn't read file ".../tcl8.6/init.tcl"`、`.../tk8.6/ttk/*.tcl`、`icons.tcl` 等（错误为 “no such file or directory” 或 “No error”）。失败用例随机（含 `test_nav_item_switches_workspace`、`test_saved_group_height_has_safe_bounds[-100]`、`test_article_workspace_group_height_persists` 等），与热度模块改动无关。

已验证并排除：同进程 400 次纯 `tk.Tk()` 创建/销毁 0 失败；测试中禁用 OCR 预热线程（12 次中仍有 2 次失败）；会话内关闭自动 GC、只在主线程回收（15 次中仍有 3 次失败）。虽然“后台线程析构 Tcl 解释器”能在最小复现中造成崩溃，但两种隔离措施都未降低失败率，因此不能认定为测试隔离问题，未修改测试或 conftest。更可能与 Windows 上读取 Python Tcl 库文件时的外部干扰（安全软件扫描、文件句柄竞争等）有关，需要进一步在系统层面排查。
