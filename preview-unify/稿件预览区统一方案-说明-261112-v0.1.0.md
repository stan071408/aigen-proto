## 一、现状差异（v0.11.8）

四种稿的预览现在不是同一套组件，差别主要在这几处：

| 项目 | 原稿（第 2 步） | 三稿（3.3 / 3.4） | 三稿合稿（3.5） | 图文稿（第 4 步） |
| --- | --- | --- | --- | --- |
| 容器 | `details.readonly-preview` + 内层 `article.paper`（8px 圆角、1px `#d9e3f0`） | 3.3 **不展示正文**，只给完成标签和「请到 3.4 处理」；3.4 用 `rf-frame`（12px）再套一层 `rf-preview`（8px），双边框 | 与 3.4 同壳，但顶栏是固定文案「三稿合稿」，没有方向切换 | `ill-browse` 图库，没有文章卡片，也几乎不展示正文 |
| 头部 / 元信息 | 标题行「原稿正文预览」+ 去 AI 化标记 + 折叠箭头，字数在行右；纸面内还有一行「原稿 · 示例 / N 字」 | 3.4 顶栏是「差异化 / 广度 / 深度」标签 +「导出全部稿件」；预览内另有「原型示例正文 · N 字」 | 顶栏仅「三稿合稿」；预览内同样有字数说明 | 「封面首图」「正文配图」两个小节标题，有「共 N 张」，没有文章标题和字数（标题在上方设置区） |
| 正文排版 | 标题约 24–27px，正文 14px / 行高 2.1，整块 `pre-wrap`，内边距约 25–30px | 3.4 预览标题是 15px 的 `h4`，正文 13px / 行高 1.95，按段拆开 | 与 3.4 相同 | 结果区只排图片：封面 16:9，正文配图 4:3 网格；`paper()` 里虽有「封面 + 正文 + 示例图」的结构，图文步骤并未使用 |
| 三稿如何呈现 | — | 3.3 只汇总状态；3.4 **标签切换，一次看一份** | 单份合稿 | — |
| 折叠 | 点整行标题折叠，自定义箭头，默认展开 | 3.4 用「预览文章 / 收起文章」文字开关，默认是否展开与原稿不一致 | 同 3.4 | 预览本身不能折；可折叠的是上方设置区 |
| 空状态 | 与 3.1 / 3.2 看齐：标题行 + 虚线居中框，撑满剩余高度 | 3.3 虚线框「三稿将在这里汇总」；3.4 某方向失败时是「这个方向还未完成」 | 合稿生成后才进入此步，几乎看不到空态 | 旧式空状态「为这篇文章，接上画面」，与第 2 步新空态不完全同一套 |
| 加载态 | 标题骨架 + 纸面多行骨架 | 3.3 是三张小骨架卡 + 进度文字 | 主要靠按钮 loading | 封面和配图的图片骨架，没有正文骨架 |
| 按钮位置 | 三个主按钮在预览框下方（导出本稿 / 进入图文生成 / 原稿深度加工） | 3.4 在预览下方：导出本稿 / 进入图文生成 / 合并三稿；顶栏另有「导出全部」 | 预览下方：导出本稿 / 进入图文生成 | 图库下方居中「导出本稿」 |

归纳成五条：

1. **不是同一套外壳**：原稿是可折叠的纸面，三稿 / 合稿是「外框 + 内层预览」，图文稿是图库，三种结构并存。
2. **三稿在 3.3 看不到正文**，要到 3.4 用标签切换逐份查看，和「核对三份差异」的诉求不一致。
3. **字号、行高、标题层级不统一**：原稿大标题 + 14px / 2.1；三稿 / 合稿是小 `h4` + 13px / 1.95；图文稿干脆不排正文。
4. **图文稿结果区只出图、不出文**，配图没有落在正文里的位置，和另外三种「文章预览」对不上。
5. **折叠方式、空状态、加载态、按钮位置** 各走各的：原稿点行折叠、按钮在框下；三稿用文字开关；图文稿不能折预览，按钮在图库下居中。

## 二、三套方案要点

三套都遵守同一约束：四种稿共用一套头部（类型、分类、字数、折叠）、同一套正文排版、同一位置的操作区，以及同一套空状态 / 加载态。差别只在「预览像什么」，以及三稿、图文稿怎么展开。

### 方案 A · 卡片并列

工作台结果卡语言。顶栏放类型 / 分类 / 字数 / 折叠箭头，正文在卡内，按钮固定在卡下。三稿是三张卡并排，一次看完三份；图文稿把封面放在标题下方，配图插在段落之间。空状态沿用第 2 步已经对齐过的「标题行 + 虚线居中框」。

### 方案 B · 文档纸面

预览像放在浅色书桌上的文稿。大标题、更疏的行距，元信息做成纸面顶端的一行小字，按钮收在纸面底部。三稿是三份纸上下叠放；图文稿把封面通栏铺在标题之上，配图以接近杂志的方式插在文中。更像阅读和导出时的样子。

### 方案 C · 标签切换

四种稿共用同一外壳，顶部标签是唯一的切换方式。原稿、合稿在标签位只显示类型名；三稿用「差异化 / 广度 / 深度」切换，一次只看一份；图文稿可在「图文混排」和「配图一览」之间切换。最接近现在 3.4 的交互，改动面最小。

---

## 三、推荐

**推荐方案 A（卡片并列）。**

理由：

1. 和工作台已经统一的 3.1 / 3.2 / 第 2 步空状态是同一套卡片语言，落回主原型时不用再换皮。
2. 项总这次要核对的是「这几种稿的预览区为什么不像」，三稿并排最容易看出统一之后长什么样，也方便以后并排看三份差异。
3. 图文混排把封面和配图直接放进同一张卡，位置一眼能看清，不再把图文稿做成和文章预览脱节的图库。
4. 方案 B 阅读感更好，但和左侧设置卡并置时会跳到另一套气质，适合以后做「导出预览 / 阅读视图」，不太适合作为工作台默认结果区。
5. 方案 C 改动最小、也保留了 3.4 的切换习惯，但一次只能看一份，统一感主要靠外壳，不利于并排核对。

若项总更看重阅读和导出时的样子，选 B；若希望尽量沿用现在 3.4 的标签切换、少改结构，选 C。
