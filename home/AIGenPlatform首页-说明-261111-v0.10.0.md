## 复现结果、根因、修复点（项总 20:39 第 2、3 图：3.2 单选点击跳走）

### 复现

用 Playwright **真实鼠标点击**（locator.click，不用 `el.click()` / `dispatchEvent`），图文生成走完第 2 步原稿 → 原稿深度加工 → 3.1 获取并选择立意 → 到达 3.2，再点「根据原标题获取 / 从已有风格中选择」。三环境（file / srcdoc `allow-scripts` / srcdoc + same-origin）× 1366×768 / 1920×1080 均测；热榜对应步为画布第 4 步（热榜引导 STEP 03「确认文章的写作风格」）。

**修复前**（file 1366 实测）：

- 点击 3.2 来源单选会触发整页 `render()`（`#content.innerHTML` 重写）。
- `sourceChange` 未走画布自带的 `keepScroll`，滚动位置被冲掉；同时第 2 步「滚到原稿结果」留下的 `S.resultPad` 在每次 `render` 后被 article 补丁写回 `#alignSpacer`，第 1 步列表下方出现约数百像素空白。
- 首次点选 3.1 立意时，画布 `render()` 因 `stage` 3→4 自动 `scrollToStep` → `alignToGuideEl`（含 450ms 后再 `scrollTo` 一次），滚动差可达 **800px 以上**，观感就是「跳到第 1 步候选列表底部 + 大块空白」。
- 点击时 `#content` 捕获阶段的 `mark()` 会按最近的 `[data-step]` 改写 `S.stage`（例如在已进入 3.2 后点 3.1 已选立意，会把 stage 拽回 3）。
- hash 不变；有时 `activeElement` 落到 `h2` 或 `body.brief`。

**修复后**：3.2 两个来源单选、再次点击已选立意、第 1 步来源标签（弹出确认则取消）的 `scrollTop` 差均为 **0px**，步骤不变，第 1 步列表底到结果卡底约 **9px**，`alignSpacer` 为 **0**。首次选中立意会展开 3.2，偶发 **约 12px** 布局位移（不跳到第 1 步、无残留空白）。

### 根因（叠加）

1. **`sourceChange` 直接 `render()`，不用 `keepScroll`**：整页重绘时文档高度瞬时变短，浏览器把 `scrollY` 钳制；之后未还原。
2. **第 2 步对齐残留**：`scrollToOriginalResult` 写入 `S.resultPad`，article 模式在每次 `render` 后无条件把该高度写回 `#alignSpacer`。进入深度加工后这块垫高仍在，表现为第 1 步列表下的大块空白。
3. **自动滚步 + 延迟对齐**：`render()` 在 `S.stage > fromStep` 时调用 `scrollToStep` → `alignToGuideEl`（先 smooth，450ms 后再 instant）。仅在同步周期还原滚动挡不住这次延迟滚动。
4. **`mark()` 按点击所在 section 改 `S.stage`**，与「只改选中态」冲突。

### 修复点

- `fieldJs`：对 `sourceChange` / `setEntry` / `setAutoDeai` / `planChange` / 首次 `chooseIdea` / `chooseStyle` 包一层钉住滚动；`render` 在无显式 `scrollTarget`（或正处于钉住）时还原 `scrollY`，内容变短时只补最小 spacer。`scrollToStep` / `alignToGuideEl` 在钉住期间空操作，并保持约 600ms 以挡住延迟对齐。已选立意/风格再点不再 `go()`。
- 单选/勾选 `mousedown` 时 `focus({preventScroll:true})`；点击后若 `mark()` 把 `S.stage` 拽回更早步骤则还原。`#content` 设 `overflow-anchor: none`。
- 进入第 3 步或深度加工后清掉 `S.resultPad`，按当前滚动回收多余 `#alignSpacer`（所有重渲染路径：切换来源、获取风格、回退清空等）。
- 钉住标志不粘滞，以免挡住之后真正的 `go()` / `scrollToStep`。

## 1. 「取消 / 重试」次要按钮与第 2 步原标题行

「取消」「重试」改为 `.btn-secondary` 描边按钮：与主按钮同高（36px）、同圆角（8px），白底 + 1px 主色描边（`#1c5fc4`），主色文字，hover 浅蓝底，可见 focus，间距 8–12px。取消带内联 SVG「×」，重试带刷新图标。「重选」等操作类 quiet 按钮同样式；「展开设置 / 清空数据」仍为链接式文字按钮（统一主色，hover 下划线）。

「榜单原标题：…」从操作行抽出，放到「指定的文章标题」下方独立一行（12px 灰字、单行省略）。右侧「生成新标题 / 去AI化 / 主按钮 / 取消」为不换行操作组，靠右；窄宽度下整组换行，不再挤压提示文字。

## 2. 统一步进器与数字控件清单

一套组件：类名 `.ctl-step`，构建函数 `window.ctlStepHTML`（`countCtl` 对非 `hotCount` 的条目改为走它）。外观：一个圆角容器、**2px** 描边 `#6b7c94`（与 v0.8 输入框规范同色），内部三格只用分隔线，无嵌套双描边。隐藏原生 spinner（`::-webkit-inner-spin-button` + `-moz-appearance:textfield`）。高度 36px，与中档输入框/主按钮一致。`focus-within` 时外框变主色蓝 + 3px 浅蓝外发光。单位（个 / 条 / 字）在步进器右侧，灰色、基线对齐。支持点击与长按连续增减、键盘上下键、min/max 钳制，非法值失焦回退到合法值，原有校验保留。
