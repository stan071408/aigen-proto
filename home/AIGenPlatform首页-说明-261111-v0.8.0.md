## 本版改动

范围：只改共用画布里与「图文生成」相关的样式 / 行为。首页、登录 / 注册、总览、管理 / 系统六页、侧栏、热榜第 1 步（独立实现）均未改版面、未改交互。共用简报画布源码（`briefSrc`）与热榜第 1 步适配（`hotJs` / `hotCss`、`embedCss`、`bridgeJs`）与 v0.7.0 逐字相同。

因热榜第 2–6 步与图文生成共用同一份画布、业务页面须一致，**第 2–6 步里相同的手输框样式已同步**（`fieldCss` / `fieldJs` 在 `article` 与 `hot` 两种模式都注入）。热榜第 1 步的 `#hotTopic` / `#hotCount` / `.hot-set` / `.hot-demo` 已显式排除，保持原 1px 描边，也不加「手动输入 / 必填」标记。热榜「生成原稿」不在本版范围：热榜流程跳过原稿步，未改热榜按钮行为；回归 41 项热榜检查全部通过。

1. **手输控件视觉规范**：图文生成里所有需人工填写的 `input[type=text|number]` / `textarea`（第 1 步主题方向、标题数、想写的主题、希望生成多少个标题、指定文章标题；以及后续每稿字数、立意 / 风格条数等）统一为「明确可输入」的外观，用 CSS 变量在 `#content` 上集中定义，不逐个硬编码。
2. **「生成原稿」改为异步请求**：第 2 步的「生成原稿」「重新生成原稿」走同一套分阶段 Promise（第 1 步直接指定「开始处理」目前仍只确认标题进入第 2 步，不自动触发生成；生成仍要点「生成原稿」，因此一并受益于同一函数）。完成后才渲染原稿、候选标题和三按钮，并按 v0.7.0 逻辑滚动到位。

## 异步生成原稿：机制、失败与取消

- 点击后立即进入进行中：按钮 `disabled`，旋转图标 + 「生成中…」，并带「取消」。顶部卡片出现进度条（「正在生成原稿…」+ 当前阶段）。
- 日志带时间戳，分阶段追加：`已提交生成请求 → 正在写作… → 正在去AI化…（若勾选）→ 已生成原稿（已去AI化）`；平台热榜来源随后还有「已选用新标题：…」。
- 使用 `async/await` + `setTimeout` 模拟，不阻塞页面。默认总延迟 2100ms（约 1.5–3 秒），均分成三段；测试可通过 `window.ORIG_DELAY` 覆盖。
- 等待期间可查看右侧导航、折叠展开；会影响结果的控件（来源标签切换、标题重选、去AI化勾选、候选标题重选）禁用，避免竞态。去AI化在点击瞬间冻结（`S.origFrozenDeai`）。
- 请求序号 `S.origSeq` + `AbortController` 防止旧请求回写。重复点击只计一次（`window.ORIG_REQUESTS`），被忽略的点击记入 `ORIG_IGNORED`。
- 失败沿用平台栏「模拟请求」的 `S.mode`（成功 / 数量不足 / 无结果 / 失败）。失败时不残留半成品（不写 `S.original` / 候选标题），按钮恢复可点，日志写失败原因，设置卡旁提供「重试」。空结果（`empty`）同样恢复按钮并可重试。
- 已实现简单取消：进行中点「取消」会 abort 当前请求、递增序号、清掉半成品、写「已取消生成请求。」。
- 切换到其他模块再回来：图文生成 iframe 保持挂载，进行中状态会继续或完成后展示结果，不会留下卡死的禁用按钮；退出登录会卸载模块。
- 不依赖原生 form submit，srcdoc 沙箱（含嵌套 iframe）可用。滚动在结果渲染完成之后触发（沿用 v0.7.0 `scrollToOriginalResult`）。

直接指定标题「开始处理」**不会自动开始生成原稿**（与 v0.7.0 行为一致，只确认标题并进入第 2 步）。说明如上，未擅自改成自动生成。

## 设置卡高度实测（差值均为 0）

因标签行增加了「手动输入 / 必填或可选」，统一高度由 v0.7.0 的 199px 调整为 **204px**。

| 环境 | 分辨率 | 平台热榜标题 | 主题生成标题 | 直接指定标题 | 差值 |
|---|---|---|---|---|---|
| file://、srcdoc allow-scripts、srcdoc allow-scripts allow-same-origin | 1366×768 | 204px | 204px | 204px | 0 |
| 同上三种 | 1920×1080 | 204px | 204px | 204px | 0 |

生成原稿后滚动实测（候选标题区顶部距画布视口顶部）：1366×768 为 8px，1920×1080 为 4px，均小于 120px。三种嵌套 / 沙箱环境结果一致。

## 行为约定与假设

1. 项总要求「清晰的 1.5px 描边」。为实现可辨认性并避开 Chromium 把 1.5px 计算成 1px，实际使用 2px（仍 ≥1.5px），颜色 `#6b7c94`。若必须视觉上恰为 1.5 物理像素，需要再指定。
2. 采集平台是勾选而非手输，只加「必填」标记，不加「手动输入」。
3. 下拉框（如配图方式 `select#imageMode`）不是自由手输，未套「手动输入 / 必填」规范，以免和填写区混淆。
4. 画布内没有单独的「核心立意 / 风格自定义」文本框，只找到立意 / 风格条数与每稿字数范围，已纳入规范。
5. 「生成原稿」默认延迟 2.1 秒；自测里用较短 `ORIG_DELAY` 覆盖。v0.7.0 里「点生成原稿后立刻出现结果」的同步假设，已改为先断言进行中、再等待异步完成。
6. 热榜第 1 步输入框刻意保持原样；第 2 步「生成条数」等已同步新手输样式（回归中有断言）。
